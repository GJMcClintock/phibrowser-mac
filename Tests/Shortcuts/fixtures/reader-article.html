Shortcut Reader Article

A browser keyboard shortcut should continue to work when focus moves from the original article into its reading surface. This local article provides enough readable content for the installed Reader extension to extract a real document. It contains no remote assets, scripts, account data, or tracking requests.

The original page remains open underneath the reading surface. Closing the surface must reveal the same article without closing its source tab. A rebound close command should act on the current overlay, while the old command should follow the user's new configuration. An explicitly disabled command must remain disabled throughout this transition.

Legacy shortcut files can represent shifted punctuation differently from a newly recorded shortcut. For example, the plus sign may be stored with only the Command modifier, although a United States keyboard produces it with Shift and the equals key. Both representations share the same menu execution identity, and overlay matching should preserve that identity.

Extra modifiers still distinguish different commands. Testing the new shortcut together with an additional Shift or Option modifier ensures that a broad character comparison does not accidentally close the reading surface. The underlying article is retained after a matching close or navigation action.

This article is deliberately stable and served only from the local loopback interface for UI tests. Its title identifies the source tab, and the link below identifies the original web document after the Reader overlay has been dismissed. Repeated test runs create disposable browser profiles and do not depend on public websites.
